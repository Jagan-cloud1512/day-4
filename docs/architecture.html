Key Design Features

Idempotency

Every side effect runs through EquipmentDb.once() with a key derived from the run and step. Booking and notification are also safe to repeat on their own.

Crash Recovery

Worker dies → lease expires → another worker claims the run → replays from recorded steps → idempotency keys prevent duplicate bookings.

Policy in Data

Business rules (max fine, max bookings, training requirements) live in the policy and training tables, not in prompts. Tools enforce them even if the model skips the check.

Least Privilege

Inventory specialist has zero write tools. Booking specialist is bound to one student's roll number. Supervisor has only delegation tools.

Durable Queue

Lease-based job queue with heartbeat, expiration reaping, retry with exponential backoff, and dead-lettering after max attempts.

Pluggable LLM

Groq (fast inference), Gemini (Google), or scripted mocks. Same generate() interface. No API key needed for tests and demo.
